# Анализ скриптов управления камерой (Controlboard)

## 1. Общее описание
Система представляет собой инструмент командной строки (CLI) на Python для низкоуровневого управления и диагностики аппаратного комплекса (вероятно, платы управления камерой видеофиксации) через последовательный порт (COM-порт/UART).

Взаимодействие с устройством осуществляется по протоколу, похожему на **Modbus RTU** (используются функции чтения/записи регистров, CRC16 для проверки целостности данных).

### Основные файлы:
*   **`controlboard.py`**: Основной исполняемый скрипт. Обрабатывает аргументы командной строки, управляет соединением по COM-порту и реализует логику команд.
*   **`commands.py`**: Библиотека определений. Содержит словари всех доступных команд, адреса регистров, коды функций Modbus и константы конфигурации.

---

## 2. Как это работает

### Архитектура
1.  **Запуск**: Пользователь запускает `controlboard.py` с аргументами (тип действия, имя команды, порт).
2.  **Парсинг**: Скрипт определяет тип операции (`read`, `write`, `control`, `test`, `update` и др.).
3.  **Формирование пакета**: На основе имени команды из `commands.py` берется структура Modbus-запроса (адрес устройства, функция, регистр, значение).
4.  **Транспорт**: Пакет дополняется контрольной суммой CRC16 и отправляется в указанный COM-порт.
5.  **Ответ**: Скрипт ожидает ответ от устройства, проверяет его CRC16 и декодирует данные (например, переводит байты в температуру, напряжение или статус).

### Протокол
Используется стандартная структура кадра Modbus RTU:
`[Адрес] [Функция] [Регистр Hi] [Регистр Lo] [Значение Hi] [Значение Lo] [CRC Lo] [CRC Hi]`

Адрес устройства по умолчанию: `0x30` (48).

## 3. Основные возможности и команды

Скрипт поддерживает несколько режимов работы (subparsers):

### 3.1. Чтение данных (`read`)
Используется для получения телеметрии и текущих настроек.
*   **Сенсоры**: `temp` (температура), `voltage` (напряжение), `current` (ток), `humidity` (влажность), `pressure` (давление).
*   **Состояния**: `coils` (цепи питания), `states` (флаги ошибок, AC_OK, Battery Low), `pc_wdt` (таймер сторожевого пса ПК).
*   **Счетчики**: `accum` (потребленная энергия), `timer` (время работы).
*   **IMU**: `imu` (данные акселерометра и гироскопа).
*   **Информация**: `version_request` (версия прошивки), `serial_number` (серийный номер МК).

**Пример запуска:**
```bash
python controlboard.py read temp -p COM3
```

### 3.2. Управление (`control`)
Команды прямого действия (вкл/выкл).
*   **Периферия**: `radar_on`/`off` (радар), `cam_on`/`off` (камера), `gps_on`/`off`, `pc_on`/`off`.
*   **Индикация**: `led1_on`/`off`, `led1_1hz` (мигание).
*   **Системные**: `reset` (сброс МК), `pc_wdt_reset` (сброс ватчдога), `params_save` (сохранение настроек во Flash).

**Пример запуска:**
```bash
python controlboard.py control cam_on -p COM3
```

### 3.3. Запись настроек (`write`)
Изменение конфигурационных параметров. Некоторые команды требуют аргумент `-v` (значение).
*   **Нагреватели**: `heater1_temp`, `heater2_temp` (температурные пороги).
*   **Лимиты**: `max_volt`, `min_volt`, `max_current` (защитные пороги по питанию).
*   **Моторы**: `focus`, `zoom`, `diaph` (управление объективом). Принимают значения вида `>100` (по часовой) или `<100` (против).
*   **RTC**: `rtc` (установка времени).

**Пример запуска:**
```bash
python controlboard.py write focus -v ">500" -p COM3
```

### 3.4. Обновление прошивки (`update`)
Специальный режим для прошивки устройства `.hex` файлом.
*   Поддерживает загрузку Bootloader, Factory Firmware и Update Firmware.
*   Автоматически стирает память, пишет данные построчно и проверяет результат.

**Пример запуска:**
```bash
python controlboard.py update -f firmware.hex -p COM3
```

### 3.5. Тесты (`test`)
Запуск встроенных сценариев тестирования.
*   `leds`: Проверка всех светодиодов.
*   `sensors`: Опрос всех датчиков.
*   `motors`: Тест приводов объектива.

## 4. Важные особенности использования

1.  **Зависимости**: Требуется библиотека `pyserial` (`pip install pyserial`). Для работы с CP2105 (USB-UART мост) на Windows может потребоваться DLL `CP210xManufacturing.dll`.
2.  **Порт**: Обязательный аргумент `-p` (или `--port`). На Windows это `COMx`, на Linux `/dev/ttyUSBx`.
3.  **Baudrate**: По умолчанию `19200`. Можно изменить через `-b`.
4.  **Безопасность**:
    *   Команда `reset` перезагружает плату.
    *   Команды `write` меняют настройки, которые могут сохраниться в энергонезависимую память (если выполнить `params_save`).
    *   Некорректное использование команд управления моторами (`focus`, `zoom`) может повредить механику объектива (если нет концевиков/защиты).
5.  **Утилиты**: Есть команда `util CP2105_RST` для программного сброса USB-хаба/конвертера CP2105, что полезно при зависании порта.

## 5. Рекомендации
*   Перед использованием команд записи (`write`) рекомендуется сначала считать текущее значение (`read`), чтобы знать исходное состояние.
*   Для диагностики проблем с питанием используйте `read coils` и `read states` — они показывают состояние всех силовых ключей и флагов аварий.

## 6. Устранение неполадок (Troubleshooting)
На основе опыта эксплуатации (из контекста Gemini):

### 6.1. Ошибка "Invalid CRC16"
Если при чтении данных (например, `read version_request`) возникает ошибка CRC, причины могут быть следующими:
1.  **Конфликт служб**: Системные службы `edgeserver` и `vsmd` могут занимать порт.
    *   **Решение**: Остановить их перед работой:
        ```bash
        sudo service edgeserver stop
        sudo service vsmd stop
        ```
2.  **Неверный порт**:
    *   На устройствах с чипом **CP2105** (Dual USB to UART) обычно создаются два порта (например, `/dev/ttyUSB1` и `/dev/ttyUSB2`).
    *   Один порт — **консольный** (может спамить данными, вызывая ошибки CRC).
    *   Второй порт — **Modbus** (тот, который нужен).
    *   **Решение**: Попробуйте соседний порт (например, если `ttyUSB1` не работает, попробуйте `ttyUSB2`).
3.  **Скорость (Baudrate)**: Убедитесь, что скорость совпадает (по умолчанию 19200).

### 6.2. Поиск правильного порта
Используйте команды диагностики:
*   `dmesg | grep tty` — покажет, какие устройства подключились.
*   `lsusb` — покажет наличие чипов (CP2105 vs CP2102).
*   `udevadm info -a -n /dev/ttyUSBx | grep '{product}'` — покажет описание устройства.

## 7. Скрипты автоматизации и утилиты
В репозитории присутствуют дополнительные скрипты, упрощающие работу:

### 7.1. `app.py` (Интерактивная консоль)
REPL-оболочка для работы с устройством без постоянного перезапуска скрипта.
*   **Запуск**: `python app.py`
*   **Особенности**:
    *   Держит COM-порт открытым постоянно (ускоряет работу).
    *   Поддерживает историю команд.
    *   Позволяет вводить команды в формате `read temp`, `control led1_on`.

### 7.2. `setup.sh` (Настройка окружения)
Bash-скрипт для быстрой настройки рабочего места.
*   **Функции**:
    *   Устанавливает системные зависимости (`python3-venv`).
    *   Создает виртуальное окружение `env` и ставит `pyserial`.
    *   Добавляет пользователя в группу `dialout` (права на COM-порт).
    *   Синхронизирует файлы с GitHub.
    *   Запускает интерактивное меню.

### 7.3. `autoflash.sh` (Авто-прошивальщик)
Скрипт для безопасного обновления прошивки.
*   **Алгоритм**:
    1.  Останавливает конфликтующие службы (`edgeserver`, `vsmd`).
    2.  Автоматически ищет порт контроллера (перебирает `/dev/ttyUSB*`).
    3.  Пытается заморозить Watchdog ПК (чтобы компьютер не перезагрузился во время прошивки).
    4.  Запускает `controlboard.py update`.
    5.  Ведет лог обновлений в `~/smalledge_fw_version`.
    6.  Перезапускает службы после завершения.

### 7.4. `run.sh` (Быстрый запуск и обновление)
Создается автоматически при первом запуске `setup.sh`.
*   **Назначение**: Позволяет быстро перезапустить меню управления и обновить скрипты без ввода длинной URL-ссылки.
*   **Как работает**: Скачивает актуальную версию `setup.sh` с GitHub и запускает её.
*   **Использование**: `./run.sh` (в папке установки).

## 8. Важные технические детали
Моменты, которые не были очевидны сразу, но важны для эксплуатации:

### 8.1. Системные требования
*   **Python 3.10+**: Скрипты жестко требуют версию Python не ниже 3.10 (используются новые возможности языка, например `match/case`). Скрипты `setup.sh` и `autoflash.sh` автоматически проверяют это.

### 8.2. Логирование данных
Скрипты создают полезные файлы в процессе работы:
*   `~/smalledge_fw_version`: Журнал истории прошивок (создается `autoflash.sh`). Содержит дату и версию каждой установленной прошивки.
*   `imu_data_log.csv`: Файл с "сырыми" данными акселерометра и гироскопа. Создается при запуске теста `test imu_data_to_file`.

### 8.3. Безопасность обновления (Watchdog)
Скрипт `autoflash.sh` делает критически важную вещь перед прошивкой: **замораживает аппаратный Watchdog** (таймер перезагрузки).
*   Если этого не сделать, Watchdog может перезагрузить компьютер прямо во время процесса прошивки контроллера, что приведет к "окирпичиванию" устройства.
*   Скрипт делает 3 попытки заморозки и сброса таймера на 120 секунд. Если это не удается — прошивка отменяется ради безопасности.
